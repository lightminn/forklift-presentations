# 4주차 자료 출처

수치는 모두 로봇 저장소(`forklift/`)의 검증 기록과 계획 문서에서 가져왔고, 사진을 제외한 모든 그림은
그 저장소의 커밋된 코드·설정으로 생성했다. 손으로 그리거나 추정한 값은 없다.

## 화면을 만든 것

| 만든 것 | 쓰인 곳 | 성격 |
|---|---|---|
| **실물 사진** | 차체 입고와 구조 확인 · 기존 전장과 제어 경로 | 2026-09-23 촬영. EXIF 제거·크롭한 공개용 사본이며 원본과 화소가 같지 않다 |
| **Isaac Sim** | 임무 한 사례 | 조감 고정 시점의 실행 녹화. 전 구간을 3배속으로 줄였다 |
| **측정값 도식** | 카메라 파라미터 규약 오류 | 왼쪽은 두 규약의 모식도, 오른쪽은 실측 두 점과 0.5 화소에서 계산한 선 |
| **공식 사양 도식** | 카메라 장착 조건 | 아래 RealSense 공식 문서의 값으로 그렸다. 448 mm 만 우리가 계산한 값이다 |
| 도식 | 개발 진행 현황 · 다음 작업 | 저장소 기록에서 직접 그린 그림 |

## 수치

| 수치 | 값 | 출처와 정의 |
|---|---|---|
| 높이 편향 평균 | +2.996 mm → +0.0002 mm | `docs/validation/2026-09-21-g1-calibration-run.md` §5.1. **교정 측정에서 복원한 높이의 평균 편향**이며 포켓 위치 정확도나 실센서 정밀도가 아니다 |
| 거리별 판정 | 0 / 285 → 285 / 285 | 같은 문서 §5.1. 같은 교정 측정의 거리별 수치 게이트 통과 수 |
| 주점 규약 차이 | 0.5 화소 | 같은 문서 §3.3. Isaac 은 `cx = width × 0.5 = 320.0`(화소 중심이 반정수), 검출기는 `np.indices()` 의 정수 인덱스 |
| 인식 위치 오차 | 2.58 mm → 2.53 mm | 같은 문서 §3.5. **기존 성공 5건을 두 규약으로 재계산한 평균.** 개별로는 개선과 악화가 섞인다 |
| 임무 시간 | 75.4초 (예산 150초) | `docs/plans/2026-09-17-project-status-and-next-steps.md` §1b. 실행 `20260922T0600Z_video_seed2` |
| 삽입 깊이 | 360 mm | 같은 절. 규칙 `min(깊이 × 0.6, 406 − 46 mm)`. **운영 목표이고 안전 합격 조건이 아니다** |
| 삽입 종점 오차 | 7.65 mm / 2.83 mrad | 같은 절. **계획 종점 대비 추종 오차**이지 실제 포켓 기준 정밀도가 아니다 |
| 중첩 검사 여유 | 2 mm | 같은 절. 검사 **시점마다**의 3차원 상자 검사. 연속 무접촉 증명도 접촉력 측정도 아니다 |
| 차체 구성·부품 표기 | — | `docs/validation/2026-09-23-chassis-intake.md` §2. 육안 관찰과 라벨 판독뿐이며 치수·정격은 포함하지 않는다 |
| 하네스 | 색 구분 여러 가닥 | 같은 문서 §2.3. **가닥 수를 정확히 세지 않았고** 각 심선의 종단도 추적하지 않았다 |

## 카메라 장착 조건(5쪽)의 외부 출처

| 내용 | 출처 |
|---|---|
| 팔레트 검출 카메라를 **지면 위 23~36 cm, 바닥·팔레트면에 수직**으로 장착 | ifm PDS 통합 안내 <https://www.ifm.com/gb/en/shared/technologies/o3d/pallet-detection-system-pds/integration-of-the-pds> |
| 포크 캐리지 장착, 포크가 시야 하단에 오도록 | Crown 특허 US9990535B2 <https://patents.google.com/patent/US9990535B2/en> |
| 백레스트(캐리지 일체) 장착, 카메라와 포크는 강체 관계 | Kita & Kato, *Sensors* 2026 <https://pmc.ncbi.nlm.nih.gov/articles/PMC12788346/> |
| 최종 접근은 근거리 전용 센서가 담당 | ADAPT 자율 지게차 <https://arxiv.org/html/2503.14331v1> |
| 깊이 화각 87° × 58°, 권장 범위 0.3~3 m | Intel RealSense D435i 제품 사양 <https://www.realsenseai.com/products/depth-camera-d435i/> |
| 해상도별 최소 측정 거리 280 / 195 / 105 mm, 깊이 오차는 거리의 제곱에 비례 | RealSense 튜닝 문서 <https://dev.realsenseai.com/docs/tuning-depth-cameras-for-best-performance/> |
| **448 mm** — 팔레트 전면 800 mm 가 가로 화각에 들어오는 최소 거리 | 데이터시트 §4.4 의 기준선 보정 공식으로 **우리가 계산한 값**이며 제조사 발표치가 아니다 |

⚠️ 후진 카메라와 포크 안쪽 카메라(Orlaco ForkView 등)는 **운전자 시야 보조**이고 포켓 검출 센서가 아니다.
두 용도의 장착 관행을 섞지 않는다.

⚠️ 「마스트 상단에 달면 최종 접근에서 포켓을 놓친다」고 정량적으로 주장한 문헌은 찾지 못했다.
문헌은 이 문제를 화각 확보, 근거리 전용 센서로의 인계, 접근 중 카메라 상승으로 다룬다.
이 자료도 그렇게 적었고 단정하지 않는다.

## 영상

`assets/08_mission_seed2.mp4` 는 로봇 저장소의 `videos-from-ws1/seed2_transport.mp4`(75.3초 · 1280 × 720 ·
60 fps)를 **전 구간 3배속**으로 줄이고 1120 × 630 으로 축소한 것이다. 구간을 잘라내지 않았다.
**영상 재생 시간 25.1초와 임무 시간 75.4초를 같은 수로 읽지 않는다.**

## 이 자료가 말하지 않는 것

- **실물 성능.** 차체는 입고됐으나 치수·질량·정격을 하나도 재지 않았고 통전 시험도 하지 않았다.
- **실물 카메라 교정.** 규약 오류 수정은 Isaac 입력 경로와 해당 교정 장면에 대한 것이고 실물 D435i 가 아니다.
- **여러 조건의 성공률.** 규약 수정이 검출 입력을 바꾸어 이전 성적은 무효이며 재실행하지 않았다.
- **잠정 모델의 확정.** 전면 `DLS` 각인은 확인했으나 SKU 동일성과 카탈로그 치수는 미확인이다.
- **동봉 팔레트의 규격.** 치수를 재기 전이므로 로봇 저장소 `docs/decisions/0002-test-pallet-and-geometry-generality.md` 의 시험 형상 결정을 대신하지 않는다.
- **지도 작성·위치 추정·근접 포켓 추적.** 3주차에 이어 여전히 미구현이다.

## 3주차 피드백 대응

교수님이 3주차에 주신 세 가지 중 **"실제 지게차의 RGB-D 장착 확인 후 우리 차체에 스케일링"만**
이번 주에 다룬다(5쪽). 나머지 둘(지게차 표준 운용 방법, 시험용 팔레트 제작 방법)은 다음 주에
실측과 함께 조사해 보고한다고 10쪽에 적었다.
